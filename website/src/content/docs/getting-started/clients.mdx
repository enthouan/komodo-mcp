Each recipe launches the executable over stdio and supplies the Core connection through the server’s environment. Replace the executable placeholder with the absolute path printed by the [native archive installation](/getting-started/#native-stdio). For a source build, use the absolute path to `target/release/komodo-mcp`.

<Aside type="note" title="What “reviewed” means">
  Each recipe's syntax was compared with the client's own documentation on the date shown. That is configuration review, not evidence of a successful connection, tool discovery, or Core read in that client. Recorded connection evidence is listed under [Compatibility](/getting-started/compatibility/).
</Aside>

The recipes set all four optional grants to `"false"`, so the server stays read-only even if the launching environment enables a grant. Change a grant only deliberately, and restart the server afterward. See [Configuration](/reference/configuration/#local-capabilities-and-core-permissions).

## Other clients and MCP Inspector

Any MCP client that can launch a local stdio process works the same way: run the absolute executable path with no arguments and set the environment variables. For a scripted check without a model, the [interactive stdio walkthrough](/docs/mock-stdio/) generates a verified MCP Inspector 2.14.0 configuration against a synthetic mock Core and lists stacks from the CLI.

## If the server does not connect

- **The client cannot start it:** check that the configured path is absolute and points to the executable from the verified archive or your local build.
- **It starts, then closes during initialization:** the startup `GetVersion` probe failed. Read the server's stderr for `configuration`, `authentication`, `unreachable`, or `timeout` and follow [Troubleshooting](/guides/troubleshooting/).
- **It connects but tools are missing:** inspect the server’s [tool selection](/reference/configuration/#select-individual-tools) and local grants, restart it after changes, and run `tools/list` again.
- **`list_stacks` returns an empty list:** the identity can read no Stacks. Check Core Read permissions; an empty list is not an error.
