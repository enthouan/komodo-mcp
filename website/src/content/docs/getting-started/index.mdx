You need access to a running Komodo Core and a scoped account with Read on a Stack you recognize. Create an API key for that account and keep its secret in your credential store. [Prepare Core credentials](/getting-started/komodo-credentials/)

Choose [native stdio](#native-stdio) if your client can launch a process on this machine. Choose [Docker Compose](#docker-compose) for a persistent Streamable HTTP endpoint. Both routes use the same three read-only tools.

## Native stdio

Use 64-bit Linux or macOS 15 or later on the machine that launches your MCP client. For releases starting with v1.0.0, [verify the signed native provenance and SBOM](/docs/stable-verification/#verify-a-native-download) before extracting the archive.

{previewCandidate ? <CandidateDownload kind="native" /> : <>
  <p>Download the archive for the client host and <a href={CHECKSUMS_URL}>SHA256SUMS</a> from the same release into a new directory.</p>
  <ul>{NATIVE_DOWNLOADS.map(({label, href}) => <li><a href={href}>{label}</a></li>)}</ul>
</>}

<Code lang="sh" title="Verify the archive and print the server command" code={`(
  set -eu
  case "$(uname -s)-$(uname -m)" in
    Darwin-arm64) target=aarch64-apple-darwin ;;
    Darwin-x86_64) target=x86_64-apple-darwin ;;
    Linux-aarch64|Linux-arm64) target=aarch64-unknown-linux-musl ;;
    Linux-x86_64) target=x86_64-unknown-linux-musl ;;
    *) exit 1 ;;
  esac
  archive="komodo-mcp-v${previewCandidate?.version ?? INSTALLATION_RELEASE_TAG.slice(1)}-$target.tar.gz"
  awk -v f="$archive" '$2 == f {print; n++} END {if (n != 1) exit 1}' SHA256SUMS > "$archive.sha256"
  if command -v sha256sum >/dev/null; then sha256sum -c "$archive.sha256"; else shasum -a 256 -c "$archive.sha256"; fi
  mkdir extracted
  tar -xzf "$archive" -C extracted
  executable="$PWD/extracted/\${archive%.tar.gz}/komodo-mcp"
  test -x "$executable"
  printf '%s\\n' "$executable"
)`} />

Configure the client to launch the printed absolute path with no arguments. Give the child process the Core address, key and secret through your client's private environment. Select `list_stacks,get_stack,stack_diagnose` and set all four optional grants to `false`. For example, this Claude Code project entry reads the three Core variables from the environment that launches the client. Replace the command path before starting a session.

```json title=".mcp.json"
{
  "mcpServers": {
    "komodo": {
      "type": "stdio",
      "command": "/absolute/path/from/the/previous/command/komodo-mcp",
      "args": [],
      "env": {
        "KOMODO_TRANSPORT": "stdio",
        "KOMODO_ADDRESS": "${KOMODO_ADDRESS}",
        "KOMODO_API_KEY": "${KOMODO_API_KEY}",
        "KOMODO_API_SECRET": "${KOMODO_API_SECRET}",
        "KOMODO_ENABLED_TOOLS": "list_stacks,get_stack,stack_diagnose",
        "KOMODO_ALLOW_OPERATE": "false",
        "KOMODO_ALLOW_CONFIGURATION_EDIT": "false",
        "KOMODO_ALLOW_PRUNE": "false",
        "KOMODO_ALLOW_TERMINAL": "false"
      }
    }
  }
}
```

Keep any inherited tool denylist consistent with the selected tools. Approve the server in the client, reconnect, and [verify discovery and your first read](#verify-your-first-read). [Other stdio client configurations](/getting-started/clients/)

## Docker Compose

Use Docker with Compose v2 and Linux containers on amd64 or arm64. Work in a new private deployment directory. The host publishes the endpoint on loopback. For releases starting with v1.0.0, [verify the image digest, SBOM and signing workflow](/docs/stable-verification/#verify-the-container-and-its-sbom).

{previewCandidate ? <CandidateDownload kind="container" /> : <>
  <p>Download the <a href={COMPOSE_URL}>versioned Compose file</a> for the published image.</p>
  <Code lang="sh" title="Get the Compose file" code={`curl --fail --show-error --location --output compose.yaml ${COMPOSE_URL}`} />
</>}

```sh title="Prepare the private environment file"
(umask 077 && touch .env) && chmod 600 .env
```

In the private `.env` file, enter your Core credentials and an independently generated inbound token (at least 32 random bytes). Put the same token in your HTTP client's credential store. The Core address must be reachable from inside the container. Use a shell with no conflicting exported Komodo settings.

<Code lang="text" title=".env" code={`KOMODO_ADDRESS=https://core.example.test
KOMODO_API_KEY=<scoped Core key>
KOMODO_API_SECRET=<scoped Core secret>
KOMODO_HTTP_TOKENS=<inbound MCP client token>
KOMODO_MCP_IMAGE=${previewCandidate ? `komodo-mcp-candidate:git-${previewCandidate.revision}` : RELEASE_IMAGE}
KOMODO_ENABLED_TOOLS=list_stacks,get_stack,stack_diagnose
KOMODO_ALLOW_OPERATE=false
KOMODO_ALLOW_CONFIGURATION_EDIT=false
KOMODO_ALLOW_PRUNE=false
KOMODO_ALLOW_TERMINAL=false`} />

```sh title="Start and check the listener"
docker compose --env-file .env config --quiet &&
  docker compose --env-file .env up -d --wait komodo-mcp
docker compose --env-file .env ps komodo-mcp
```

Once the service is healthy, add a **Streamable HTTP** server in your MCP client. Set the URL to `http://127.0.0.1:3000/mcp` and send `Authorization: Bearer <inbound MCP client token>` on every request. Keep the Core credentials in the server environment. For a remote connection use a trusted HTTPS reverse proxy. [GHCR package](https://github.com/users/enthouan/packages/container/package/komodo-mcp) · [Digest pin, private CA and health check](/docs/container/)

For example, make the client token available as `KOMODO_MCP_BEARER` in the shell that launches Claude Code. Add this project entry to `.mcp.json`. For a browser client, configure its exact origin in `KOMODO_HTTP_ALLOWED_ORIGINS` on the server. [Client configuration syntax](https://code.claude.com/docs/en/mcp#environment-variable-expansion-in-mcpjson) · [HTTP settings](/reference/configuration/#authenticated-streamable-http)

```json title=".mcp.json"
{
  "mcpServers": {
    "komodo": {
      "type": "http",
      "url": "http://127.0.0.1:3000/mcp",
      "headers": {"Authorization": "Bearer ${KOMODO_MCP_BEARER}"}
    }
  }
}
```

Connect with the bearer and [verify discovery and your first read](#verify-your-first-read).

## Verify your first read

1. Open a fresh session. Check the initialization response for `serverInfo.name` equal to `komodo-mcp` and version <code>{previewCandidate?.version ?? INSTALLATION_RELEASE_TAG.slice(1)}</code>.
2. Run `tools/list`. Expect exactly `get_stack`, `list_stacks` and `stack_diagnose`.
3. Call `list_stacks` with the arguments below. A successful response contains up to one Stack in `result.structuredContent.items`. Check its ID or name against the inventory visible to the account. If you expected a Stack and the result is empty, check the account's Core Read grants.

```json title="tools/call parameters"
{"name":"list_stacks","arguments":{"page":0,"page_size":1}}
```

See the [tool catalog](/reference/tools/), [troubleshooting](/guides/troubleshooting/), [support policy](/docs/stable-support/) and [upgrade and rollback guide](/docs/upgrade-v1/).
