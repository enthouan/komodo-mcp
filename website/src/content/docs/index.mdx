## Start by listing your stacks

Once you’ve [connected to Core](/getting-started/), ask your client to find a Stack you recognize. The first read uses your account’s permissions and returns the ID you can use to investigate a rollout.

```text wrap title="Ask your MCP client"
List the stacks I can access in Komodo and show their current status.
Use list_stacks and do not change anything.
```

<Steps>
1. **Check the available tools.** Open your client’s tool list. The getting-started configuration exposes `list_stacks`, `get_stack` and `stack_diagnose`.

2. **Read one page.** Ask the client to call `list_stacks` with `page: 0` and `page_size: 10`. Find the Stack’s name, state and ID in the result. Follow `next_page` if you need the next ten.

3. **Follow up on a failure.** Pass the returned ID to `get_stack` to confirm the target, then to `stack_diagnose`. Ask for the affected services, the evidence behind the diagnosis and anything Core couldn’t report. The [diagnosis walkthrough](/docs/operator-quickstart/) shows an example.
</Steps>

## Useful by design

To try these workflows after the three-tool setup, add the tools shown below to your server’s [tool selection](/reference/configuration/#select-individual-tools), then restart and reconnect your client.

<CardGrid>
  <Card title="Find the workload that needs attention" icon="list-format">
    Start with the Servers and Stacks your account can see. Ask for a fleet health summary to find which workloads are unhealthy and where observations are missing.

    `list_servers → list_stacks → fleet_health`
  </Card>

  <Card title="Explain a failed rollout" icon="magnifier">
    Diagnose one Stack, then follow the cited update and inspect a short log tail. Use the affected service and its evidence to explain what went wrong.

    `stack_diagnose → get_update → get_stack_logs`
  </Card>

  <Card title="Deploy a staging Stack" icon="rocket">
    Confirm the target and scope on a staging instance with the operate grant. Submit the approved deploy once, wait on its update ID, then check the Stack’s health.

    `get_stack → deploy_stack → wait_for_update → stack_diagnose`
  </Card>

  <Card title="Review pending ResourceSync changes" icon="code-branch">
    Read a sync’s cached changes and review the resources you select. The review shows proposed creates, updates and deletions and leaves them unapplied.

    `get_resource_sync_pending → review_resource_sync_pending`
  </Card>
</CardGrid>

## Know when to use it

Use Komodo MCP to inspect your fleet, trace a failed rollout or carry out a reviewed operation from your MCP client. Use Komodo Core directly to set up the instance, create API keys and decide which resources an account can access.

See [Security & Data](/guides/security/) for what your client receives, [Configuration](/reference/configuration/) for server settings, or the [FAQ](/guides/faq/) for hosting and permission questions.

<CardGrid>
  <GuideLinkCard icon="puzzle" title="Tool catalog" href="/reference/tools/" action="Look up a tool">
    Use `fleet_health` to find a workload that needs attention. For a failed Stack, `stack_diagnose` brings together its history, alerts and recent logs. Each catalog entry lists inputs, results, required grants and whether the tool makes changes.
  </GuideLinkCard>

  <GuideLinkCard icon="approve-check-circle" title="Stable support policy" href="/docs/stable-support/" action="Check your setup">
    Live tests on Linux x86-64 cover native stdio and authenticated HTTP with Core and Periphery 2.3.2. Look up your platform and MCP client to see whether the evidence comes from a live connection, a test fixture or a configuration review.
  </GuideLinkCard>

  <GuideLinkCard icon="code-branch" title="Upgrade and rollback" href="/docs/upgrade-v1/" action="Follow the upgrade guide">
    Keep your working native executable or record the current Compose image digest before you upgrade. After restarting, check that your client discovers the same tools and can read a familiar Stack. Repeat those checks if you restore the previous version.
  </GuideLinkCard>

  <GuideLinkCard icon="magnifier" title="Troubleshooting" href="/guides/troubleshooting/" action="Find your symptom">
    A `401` from `/mcp` points to the bearer token your HTTP client sends. If `list_stacks` succeeds but returns an empty list, check the Core account’s Read permission on a Stack you expect to see.
  </GuideLinkCard>
</CardGrid>
