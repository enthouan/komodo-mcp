# Client, package and service compatibility for v0.9.0

The v0.9 milestone candidate reports Cargo and MCP version `0.8.0`. Its source commit is `e8432d39d6c12c5278d26f17959f041884ab5a4c`. Live runs exercised Core 2.3.2 and Periphery 2.3.2. The distribution workflows also checked the four native archives and two OCI platforms against synthetic Core responses. [Candidate and artifact identities](releases/v0.9.0/candidate-record.json)

On both Linux transports, default inventory returned one running container. Including stopped containers produced two one-item pages. Fresh inspection of the stopped container by its returned identity matched Docker's ID, exited state, exit code 17, unhealthy status and zero restarts. A Server Read + Attach caller could list and received `permission_denied` on inspection. A direct call to a hidden tool was rejected. [Live container evidence](releases/v0.9.0/disposable-regression.md)

Stack preview submitted zero writes. Apply changed only `auto_pull` with one write. A ResourceSync reader with both local grants could review the plan. Core denied its attempted refresh, leaving zero `RunSync` submissions and the target unchanged. Changing the inline source after a separate review returned `stale_preview` with zero preflight refreshes and zero additional `RunSync` updates. After interruption following an accepted Deployment, a fresh read-only client observed the known update ID. Both runs recorded exactly one new deploy update and confirmed the container was running. All eight workload inventories and three Compose inventories were empty at teardown. [Regression scenarios and cleanup](releases/v0.9.0/disposable-regression.md)

The third run in the original study verified the frozen contract commit and file hash against the candidate record. It checked native stdout through EOF, stderr, HTTP response bodies, snapshots of the server logs and retained scenario evidence for the seeded private values. Its source rebuild reproduced the packaged Linux x86-64 executable. [Third hosted run](https://github.com/enthouan/komodo-mcp/actions/runs/45544954963) · [Original three-run study](releases/v0.9.0/disposable-regression.json)

The final run repeated the two live workflows and source rebuild on the same packages. Both live jobs verified the nested Docker daemon's Unix-only listener, the two one-item inventory pages, zero refreshes on stale apply and exactly one deployment submission after interruption. Each finished with eleven empty cleanup inventories. The HTTP job verified bridge membership, checked response status text, headers and bodies, and scanned the stopped candidate's logs and retained health diagnostics. Both clients checked decoded MCP messages for the seeded values. [Final hosted run](https://github.com/enthouan/komodo-mcp/actions/runs/45555808579) · [Evidence artifact identities](releases/v0.9.0/README.md#final-regression-artifacts)

## Fixture calls on the selected candidate

Three of six visible Stacks matched the selected Server. Each OCI job brought up its native platform with Compose, verified the running image, initialized with a bearer, discovered three selected tools and called `list_stacks` against an empty inventory. The v0.8.0 public acceptance summary links the published artifacts and outcomes. The retained successful native and Compose reports record both running service versions. Their SHA-256 values are `e0f70759152b36d8b6457604cd38a66f26e3a5cefff8053655e369d27d5f6b55` (native) and `9b662ecfffc3dee1cf067a614591f7697d142c359f96aee6de8c0a17b05100cc` (Compose). Both adapters used the same release-rehearsal initialize message. [Published acceptance](https://github.com/enthouan/komodo-mcp/issues/45#issuecomment-7145094532)

Linux arm64 native and OCI packages and the Apple silicon macOS native package passed their distribution fixtures. Live Core calls on all three arm64 packages remain untested. Other Core/Periphery version combinations, desktop clients over HTTP, Windows packages, and platforms outside the native/OCI target lists are also untested for this candidate. Performance evidence is specific to the measured workload, process and host.
